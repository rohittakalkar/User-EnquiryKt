Call Enquiry

Buyers often phone a supplier instead of sending text. Call Enquiry is four endpoints that record those calls the way Save Enquiry records text leads: callEnquiry for identified calls, callEnquiryUnidentified for anonymous ones (later claimed / linked), unidentifiedC2C to look up unclaimed calls, and linkC2CPNS to tie a virtual-number (PNS) call to IndiaMART's own record. A daily rate limit (50 unique suppliers) curbs spam calling, and identified / PNS-linked calls are pushed to Lead Management.

Call-Based Leads

Call Enquiry

GET/POST /enquiry/callEnquiry requires caller GLID, receiver GLID and a ModID (never MY), caller ≠ receiver. A bsmapping lookup returns connect_type: 2 is a hard match; otherwise a count of distinct receivers called today ≥ 50 returns HTTP 429. InsertInto PI inserts C2C_RECORDS, PU updates. callEnquiryUnidentified writes C2C_RECORDS_UNIDENTIFIED; a PU with a probable number attaches it, otherwise it attaches the real caller and chains into CallEnquiryModel. unidentifiedC2C is a read (by GA cookie, or last-5-minute unclaimed calls for a receiver). linkC2CPNS (behind middleware.Validation) links via iil_call_mapping on a 5-minute window, state pre / post.

Business flowchart

Call interactions, tracked like enquiries

Four call-tracking endpoints:

  • Identified call — caller, receiver and ModID are known; the call is rate-checked (block after 50 unique suppliers in a day) and recorded. For Message-Center / Lead-Manager screens the system also auto-detects whether the call relates to an existing enquiry (W) or a purchased lead (B), whichever is more recent.
  • Unidentified call — the buyer's account is unknown at call time; the call is saved anonymously and later claimed. An app-type claim also creates the real identified record; a PNS-type claim only attaches a probable number.
  • Unidentified lookup — a read that finds unclaimed recent calls by browser cookie or by supplier.
  • PNS link — ties a masked virtual-number call to IndiaMART's own call record within a 5-minute window, for the active (pre) and completed (post) call stages.

Identified and PNS-linked calls notify Lead Management; purely unidentified calls stay silent until claimed.

Data-flow diagram · Level 1

Where a call is recorded, identified and linked

Three call tables plus a mapping table:

  • 1.0 Identified call rate-checks via the external bsmapping service, then inserts / updates D1 and D3, and reads D4 / D5 for context.
  • 2.0 Unidentified call inserts / updates D2; an app-type claim chains into 1.0.
  • 3.0 Unidentified lookup reads D2 only.
  • 4.0 PNS link reads D1 on a 5-minute window and writes D3.
  • 1.0 and 4.0 push the shared Lead-Management queue, mirrored to Kafka.

Sequence diagram · Flows A + E

Recording an identified call, and linking a PNS call

An identified call, then a PNS link:

  1. A client posts an identified call; the API checks caller / receiver / ModID and asks the bsmapping service for a match type.
  2. alt — not a hard match and 50+ unique suppliers called today: HTTP 429. Otherwise the call is inserted (or updated) and context is auto-detected for Message-Center screens.
  3. The call is pushed to Lead Management.
  4. Later, a PNS call arrives with a pre or post state; the API looks back 5 minutes for a matching C2C record and links them via the mapping table, then pushes Lead Management.

Glossary

Business terms used above.

The four endpoints

callEnquiry
Records an identified call — the buyer's GLID is known at call time. Writes C2C_RECORDS.
callEnquiryUnidentified
Records an anonymous call (no GLID yet) into C2C_RECORDS_UNIDENTIFIED; later claimed to become identified or PNS-attached.
unidentifiedC2C
A read-only lookup (despite its POST route) for unclaimed recent calls — by browser GA cookie, or the last five minutes for a given supplier.
linkC2CPNS
Ties a masked virtual-number (PNS) call to IndiaMART's own C2C record. The only one of the four behind middleware.Validation.

Classification

PI / PU
“Post Insert” / “Post Update” — the flag that routes a request to the insert or the update path (also reused as a backup-file marker).
Hard vs soft match
The bsmapping service's connect_type: 2 = hard match (a known caller-receiver pair), anything else = soft match / no data, which triggers the rate-limit query.
Rate limit
If a caller has phoned 50 or more distinct suppliers today (and it is not a hard match), the next call is blocked with HTTP 429.
W / B context
Auto-detected only for Message-Center / Lead-Manager screens on IMOB / ANDROID / IOS: W if the call relates to an existing enquiry, B if to a purchased business lead, whichever match is more recent.
pre / post state
PNS call stages — pre (active / ringing, uses the PNS Active id) and post (completed, uses the PNS id); they map to LMS insertion types 2 and 3.

Records & downstream

iil_call_mapping
The cross-reference table linking a C2C record (and PNS records) with entry / last-modified timestamps.
Probable number
For a PNS-type claim on an unidentified call, only a likely buyer number / GLID is attached — no full identified record is created.
5-minute window
PNS linking and the unidentified lookup both only consider C2C records from the last five minutes.
Lead Management push
Identified calls (insertion_type 1, transaction type C) and PNS links (2 / 3, type P) go to the same sharded LMS queue that Save Enquiry uses, and are mirrored to Kafka topic ENQ_PNS_DATA.
GLID
GlobalID — the unique internal identifier for a buyer or supplier.
