Popup Details

Popup Details is the smallest feature in the KT series: a single yes / no signal recording whether a supplier marked interest in a popup shown to them. There is no history, no read API, no queue, no cron — just one upsert per supplier into one table. About thirty internal apps may call it; the supplier never calls it directly. The row always holds only the latest status.

Engagement Tracking

Popup Details

POST /popupdetails (serviceName POPUP_DETAILS). The route is exempt from the JWT / AK middleware, so the controller's own ~30-entry Gateway_v1 allowlist (checked against VALIDATION_KEY) is the only auth. Validation — GLID present and numeric, is_interested exactly 0 or 1 — runs before any DB call. One statement: INSERT … ON CONFLICT (fk_glusr_usr_id) DO UPDATE into TRACK_POPUP_MDC (meshpg), 1-second timeout.

Business flowchart

A one-bit interest signal per supplier

A single, lightweight flow:

  • A supplier sees a popup (which screen is out of scope) and picks interested / not interested.
  • An allowed internal app posts the signal; the API checks the GLID is numeric, the value is 0 or 1, and the caller is on the allowlist.
  • The status is upserted: an existing row for that supplier is overwritten with the new value and timestamp; a new supplier gets a fresh row.
  • No email or notification is sent; whatever feedback the supplier sees is up to the calling app.

Where the popup interest flag is written

One table, one write:

  • 1.0 Validate checks the GLID, the interest value and the caller allowlist — all before opening a DB connection.
  • 2.0 Upsert runs a single INSERT … ON CONFLICT DO UPDATE against D1.
  • No read endpoint, queue, consumer or cron is attached.

Sequence diagram · Flow A

Recording a popup interest signal

The whole feature in one exchange:

  1. An allowed internal app posts {glid, is_interested}.
  2. The API validates the GLID and the interest value, then checks the caller against the ~30-entry allowlist.
  3. alt — valid: a single upsert writes the latest status and timestamp; invalid: the request is rejected before any DB call.

Glossary

Business terms used above.

The signal

Popup interest
A single yes / no capture of whether a supplier marked interest in a popup. Not a profile field, not a workflow.
is_interested
1 = interested, 0 = not interested (also the default if the key is missing). Any other value is rejected.
TRACK_POPUP_MDC
The single meshpg table; one row per supplier, keyed by fk_glusr_usr_id.
Latest-only
Each submission overwrites the previous value. There is no history of how the supplier's interest changed over time.

Access

~30-app allowlist
The largest gateway allowlist in the KT series — MY, GLADMIN, TOLLFREE, Email Marketing, WEBERP, LEAP, MAPI, ENQUIRY, IMOB, SELLERMY and many more.
JWT-exempt route
The endpoint skips the usual JWT / AK token check; the VALIDATION_KEY allowlist match is the only auth gate.
Pre-DB validation
All checks run before a DB connection is opened, so invalid requests never consume one.
GLID
GlobalID — the unique internal identifier for the supplier.
