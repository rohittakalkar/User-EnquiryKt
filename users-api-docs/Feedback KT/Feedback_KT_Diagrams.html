Knowledge Transfer · Engineering

Feedback

Users give feedback in three contexts — My Feedback (general), IMSearch Feedback (search quality) and the in-app App-Rating popup. Behind the scenes the App-Rating popup calls the same My Feedback write endpoint over HTTP, so every rating lands in MY_FEEDBACKS. My Feedback notifies the internal team; App-Rating additionally emails the user on a low rating; IMSearch Feedback is pure data collection.

Product & Experience

Feedback

My Feedback and IMSearch Feedback share one write endpoint, dispatched by FEEDBACK_FLAG. Every My Feedback insert or update fires the USER_FEEDBACK queue, whose consumer mails the internal team and writes a second copy of the row into approvalPg. App-Rating adds an HTTP loopback and a conditional customer email.

Business flowchart

Three entry points, mostly one pipeline

The four flows:

  • My Feedback submit — five mandatory fields; a description under 6 characters is auto-tagged vague; the row is inserted with status P; the queue fires, the consumer emails the internal team and copies the row to approvalPg.
  • My Feedback update — an internal reviewer sets status A / D or adds a worklog remark; the same queue re-fires.
  • IMSearch Feedback — needs a query and a total-results count; one INSERT; no fan-out at all.
  • App-Rating popup — if the user is not logged in, an account is created first; the submission then loops back over HTTP into the My Feedback path; if the rating is in the “satisfied” set the flow ends, otherwise a follow-up email is queued to the user.

Data-flow diagram · Level 1

Where feedback is written, copied and mailed

One primary store, one shadow copy, and two mail paths:

  • 1.0 Validate & write checks the issue-type against D4, then writes D1 (My Feedback) or D3 (IMSearch).
  • 2.0 Internal-notify consumer reads the reporter's email and mails the feedback team.
  • 3.0 approvalPg sync writes a second copy of the My Feedback row into D2.
  • 4.0 App-Rating orchestrator optionally creates an account, then calls 1.0 over HTTP.
  • 5.0 Customer-mail consumer sends the low-rating follow-up.

Sequence diagram · Flow C

An App-Rating popup submission, end to end

An App-Rating popup submission touches two repos and can send two emails:

  1. alt — if no GLID was sent, the read API calls the user-add service to create an account first.
  2. The read API loops back over HTTP to the write API's /feedback; with no FEEDBACK_FLAG it defaults to My Feedback, so the row lands in MY_FEEDBACKS and the USER_FEEDBACK queue fires.
  3. That consumer mails the internal team and copies the row to approvalPg.
  4. alt — if the rating is in {4, 5, 6, 8} the flow returns; otherwise a customer follow-up email is queued.

Glossary

Business terms used above.

Feedback types

My Feedback
General feedback — a bug, suggestion or complaint with a title, description and optional rating. Reviewed by the internal team.
IMSearch Feedback
Feedback on search-result quality — the query, how many results came back, and a rating. Pure data collection, no notifications.
App-Rating popup
The in-app store-style rating prompt. Works even when the user is not logged in — it can create an account from just a mobile number.
HTTP loopback
The App-Rating flow does not write a table directly; it calls the My Feedback /feedback endpoint over HTTP, so every rating becomes a MY_FEEDBACKS row.
“Vague” auto-tag
A My Feedback description shorter than 6 characters is automatically marked vague, a triage signal for the internal team.

Lifecycle & routing

APPROVAL_STATUS P / A / D
A new feedback starts P (pending). An internal reviewer can set it to A (approved) or D (declined); no other value is accepted.
FEEDBACK_FLAG
The parameter that routes a request to the My Feedback or IMSearch Feedback path. Absent means My Feedback.
Issue type
An optional classification picked from MY_FEEDBACK_ISSUE_TYPE. An unrecognised ID is silently ignored, not rejected.
approvalPg copy
The consumer writes a second, independent copy of every My Feedback row into a separate approval database.
Internal notification email
Sent to feedback@indiamart.com for each new / updated My Feedback from app or HelpIM. Rate-limited under bursts.
Customer follow-up email
Sent to the user only from the App-Rating flow, and only when the rating is not in the satisfied set {4, 5, 6, 8}.

People & systems

Feedback / AppCare team
The internal inbox that receives My Feedback notifications and works the review queue.
Consumer
A background worker on a queue. Feedback has two: the internal-notify + approvalPg consumer, and a shared customer-mail relay.
GLID
GlobalID — the unique internal identifier for one user / company account. May be created on the fly by the App-Rating flow.
