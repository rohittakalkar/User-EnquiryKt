Knowledge Transfer · Engineering

TrustSeal

IndiaMART's premium, internal-only trust badge. Only the WEBERP internal system can create or edit a TrustSeal — not the supplier, not even GLADMIN — and most reads are WEBERP-gated too. A TrustSeal carries a full company-profile snapshot plus linked companies, trade affiliations, quality / safety certifications, chamber memberships and export status. It has an end date (subscription-like) and a prepended history log. No queue, no consumer, no cron.

Trust & Compliance

TrustSeal

One write controller, TYPE-dispatched: TS, TS_COMP, ALL. ALL + ACTION=I creates the seal and its first company in one call. Five read endpoints — basic, aggregated detail, generic lookup, company details, misc details — and sensitive fields (GST, email, mobile) are partially masked on reads.

Business flowchart

A premium, WEBERP-only trust badge

Only WEBERP writes; the write branches on TYPE:

  • TS — updates the TRUSTSEAL row, targeted by seal id, user id or customer-to-service id; only seals with APPROV in {M, A} are affected.
  • TS_COMP — a pre-check that the parent seal exists, then insert / update / delete of a linked company (with a “primary” flag).
  • ALL + ACTION I — creates the seal and its first company in one call.

Every change prepends a line to the seal's history text (latest first). The five reads are mostly WEBERP-gated; misc details serve linked vs available lists for trade affiliations and quality certs, and export status is a static list. Sensitive values come back masked. An expired end date makes the badge disappear; renewal is a manual WEBERP action.

Sequence diagram · Write + Read

Creating a TrustSeal and viewing its profile

A combined create, then a buyer view:

  1. WEBERP calls the write API; the gateway allows only WEBERP; both validation maps run.
  2. alt — TYPE=ALL + ACTION=I: the seal is inserted (returning its id) and its first company row is inserted. Otherwise the relevant row is updated by identifier, only if APPROV is M / A.
  3. A line is prepended to the seal's history text.
  4. Later a read joins the seal with company, registration and rating data across parallel queries and returns the profile with GST / email / mobile masked.

Glossary

Business terms used above.

The seal

TrustSeal
A premium trust badge shown on a certified supplier's storefront — a layer above basic GST verification, assigned by internal staff, not self-serve.
TRUSTSEAL_APPROV (M / A)
A row-level status char. Only seals in M or A are updated by the id-based write paths; others silently no-op. Exact meanings are unconfirmed.
End date & renewal
A TrustSeal is subscription-like — it has an end date, expires, and must be renewed. No automated-renewal job exists.
Company-profile snapshot
A full company profile (address, bank, turnover, tax numbers, employee count) is captured on the seal record itself, not just referenced.
Linked companies + primary flag
One seal can link several company records, one marked primary — e.g. a parent business with multiple registered entities.
Prepended history log
Every update prepends a line to a free-text history field so the most recent change reads first.

Write dispatch

WEBERP-only gateway
The write endpoint accepts only the WEBERP internal system — the tightest gate of the three trust domains.
TYPE = TS / TS_COMP / ALL
TS edits the seal, TS_COMP edits a linked company, ALL does both; ALL + ACTION=I creates a seal and its first company together.
ACTION = I / U / D
Insert, update or delete, applied within the chosen TYPE.
Orphan-link pre-check
A TS_COMP insert first checks the parent seal exists; a dangling company link cannot be created.

Reads & linked data

Five read endpoints
Basic seal data, aggregated profile, generic lookup, company details, misc details — each with its own field set and masking rules.
WEBERP-gated reads
Company, misc and generic-lookup reads all require modid = weberp; TrustSeal's detailed data is not a public API.
Sensitive-field masking
GST is shown with the middle characters replaced by *; email local-part and mobile digits are also partially masked on several reads.
Linked vs available lists
Trade affiliations and quality certs are read two ways — what is already linked, and what can still be added — for an “add new” dropdown.
Export status
A fixed, predefined set of options — no database lookup.
GLID
GlobalID — the unique internal identifier for the supplier the seal belongs to.
