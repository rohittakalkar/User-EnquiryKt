Flips — Social-Commerce Video

Flips surfaces a supplier's short-form video (YouTube / Instagram / Facebook) on their IndiaMART storefront. A supplier links a vendor account — by direct token or by Meta business-login — then posts and updates video content in batches. A Kafka sync consumer periodically diffs an external content feed and replays only the deltas through the same write API. Buyers see Flips videos merged with product-catalog videos in one gallery.

Business flowchart

Linking an account, posting content, and staying in sync

Three write flows plus a sync and a read:

  • Link account — Token mode upserts one row per user in GLUSR_FLIPS_MAP; Meta mode checks for a duplicate social account, inserts a detail row and auto-disables any sibling row for the same user + platform.
  • Post content — a batch insert that de-dupes on (user, flips-id, video-id) in one round-trip.
  • Update content — a batch update where only the fields present overwrite; missing fields keep their stored value.
  • Background sync — the Kafka feed is diffed into disable / update / insert sets and replayed through the write API; a failed batch is published to the fail topic.
  • Read — Flips content and product-catalog videos are merged and de-duplicated into one list.

Data-flow diagram · Level 1

Where Flips account and content data moves

Account and content share the fan-out; the sync consumer loops back through the write API:

  • 1.0 Link account upserts D1 (token) or writes D2 (Meta, with sibling auto-disable).
  • 2.0 Write content batch-writes D3 with DB-level de-dupe.
  • 3.0 Company-sync fan-out publishes FLIPS_WRITE_SERVICE after any account or content change.
  • 4.0 Kafka sync consumer reads D3, diffs against the feed, and calls 2.0 in chunks of 30.
  • 5.0 Read merged videos combines D3 with catalog videos from D4.

Sequence diagram · Flow F

Background content sync from the external feed

The sync consumer keeps all business rules by replaying through the write API:

  1. An external producer sends a fresh content snapshot for one (GLID, flips-id) on the Kafka topic.
  2. The consumer reads current content rows and diffs them by video-id into disable, update and insert sets.
  3. It calls the content write API twice — disable + update as UPDATE_FLAG=U, inserts as UPDATE_FLAG=I — chunked at 30 items, so validation and the fan-out still run.
  4. alt — if any batch fails, the original message is published to FLIPS_CONTENT_SYNC_FAIL.

Glossary

Business terms used above.

Linking & content

Vendor account — Token mode
The supplier (or an integration) supplies a direct vendor-API access token. Stored one row per user in GLUSR_FLIPS_MAP; a new token silently replaces the old one.
Vendor account — Meta mode
The supplier links via Facebook / Instagram business-login. Creates a detail row in GLUSR_FLIPS_DETAIL.
Sibling auto-disable
When a new Meta account is linked, every other detail row for the same user + platform is set to disabled — one active linked account per platform.
Content de-dupe
A DB-level WHERE NOT EXISTS on (user, flips-id, video-id); a re-posted video is silently skipped, not an error.
Partial update
Content update uses COALESCE per column, so only the fields sent are overwritten; the rest keep their stored value.

Sync & merge

Kafka sync consumer
USER_FLIPS_CONTENT_SYNC — reads current content, diffs it against an external feed snapshot, and replays the delta through the write API. It never writes the DB directly.
Diff sets
Every video-id is classified into disable (in DB, gone from feed), update (in both) or insert (feed only).
Chunk of 30
The sync consumer calls the write API in batches of at most 30 items, separately for updates and inserts.
FLIPS_CONTENT_SYNC_FAIL
The Kafka fail topic the original message is republished to if any replay batch fails.
Product-catalog video merge
Videos uploaded through the product catalog are merged into the same buyer-facing gallery as Flips content and de-duplicated by video-id.
FLIPS_WRITE_SERVICE
The generic company-sync fan-out fired after any account-detail or content change (not on a bare token refresh).

People & systems

Supplier
The seller who links a vendor account and posts content.
External vendor platform
YouTube / Instagram / Facebook — where the video is actually hosted and processed. IndiaMART only stores links and metadata.
Buyer
Sees the merged video gallery on the supplier's storefront.
GLID
GlobalID — the unique internal identifier for one user / company account.
