Knowledge Transfer · Engineering

Market Place URL

Links a supplier's Google Business / Facebook / Instagram URLs onto the IndiaMART profile — a third-party-presence trust signal. Insert-or-update per platform with a history trail; only four gateways may write. Two reads: a dedicated endpoint returning the latest URL per platform, and a buyer-profile embed that returns one arbitrary row. A downstream RabbitMQ consumer keeps a buyer-profile replica in sync — but no publisher was found in the current write code.

Market Place URL

Business flowchart

Three platform links with a history trail

One write endpoint, branching on the operation flag:

  • After the gateway check (one of four callers) and the mandatory-field check, the platform is resolved to a sequence number — an unknown platform gets sequence 0 and is not rejected.
  • OP_FLAG=I — insert; a URL value is required.
  • OP_FLAG=U with a row id — a metadata-only update; the URL value is left untouched.
  • OP_FLAG=U without a row id — a full update of the URL value that also resets the enrichment fields to null.
  • Every change records a history trail (who, when, from which IP / screen).

The dedicated read returns the latest URL per platform; the buyer-profile embed returns a single, effectively arbitrary row.

Sequence diagram · Flow A

Writing a marketplace URL and reading it back

A write, then the dedicated read:

  1. The API checks the gateway and mandatory fields and resolves the platform sequence.
  2. alt — OP_FLAG=I: insert (URL required). OP_FLAG=U with a row id: metadata-only update. Otherwise: full update of the URL plus nulling the enrichment fields.
  3. A history-trail row is recorded and the API returns “INSERT / UPDATE SUCCESS”.
  4. The dedicated read returns the latest URL per platform via a window function. A RabbitMQ consumer would replicate to the buyer-profile DB, but no publisher is wired in current code.

Glossary

Business terms used above.

The record

Three platforms
Google Business, Facebook and Instagram — the only recognised platforms.
Platform sequence
A number derived from the platform name (Google = 1, Facebook = 2, Instagram = 3). An unknown platform gets sequence 0 and is silently accepted, not rejected.
OP_FLAG I / U
Insert or update. Insert requires a URL value; update may or may not carry one.
Metadata-only update
When a row id is supplied on OP_FLAG=U, only enrichment / history fields change — the URL value is left as-is.
Full update
When no row id is supplied on OP_FLAG=U, the URL value changes and the enrichment fields are reset to null.
History trail
Every change records who / when / from which IP and screen; the previous value is not fully overwritten.

Access & reads

Gateway allowlist
Only GLADMIN, Weberp, SELLERMY and MY (the supplier's own app) may write.
Dedicated read
/mrkturl returns the latest URL per platform, deduped with a ROW_NUMBER() window function.
Buyer-profile embed
The /buyerprofile response embeds one marketplace-URL row via LIMIT 1 with no domain filter and no ORDER BY — effectively an arbitrary row.
String-match success check
The API decides success purely by whether the internal output string equals “INSERT SUCCESS” / “UPDATE SUCCESS”.

The replica gap

USER_MKTP_URL consumer
A live, fully-implemented RabbitMQ consumer that writes a buyer-profile copy of the table on insert / update messages.
No publisher found
The current write controller and model never publish to that queue, so the buyer-profile copy may be stale or maintained by an out-of-repo mechanism.
GLID
GlobalID — the unique internal identifier for the supplier.
