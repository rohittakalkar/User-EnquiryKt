Knowledge Transfer · Engineering

Social Review

Links a supplier's external Google Business / Facebook reviews onto their IndiaMART profile. Two steps: link an account (per platform + location), then sync individual reviews in batches of at most 20. One location per platform is active at a time — connecting a new one deactivates the old (hidden, not deleted). No moderation (already-moderated external content), no queue, consumer or cron — the external sync system calls the two write APIs like any client.

Social Review

Account link is a transactional upsert that also deactivates sibling locations; content sync resolves the active location, then upserts each review (deduped on the platform review id). Reads serve per-platform paginated reviews or a top-N-per-platform view, and never return the refresh token.

Business flowchart

Bringing external Google / Facebook reviews onto the profile

Three write flows and a read:

  • Account link (FLAG=I) — after the gateway check (FLIPS / MAPI), an upsert marks this location active (display_status = 1) and, in the same transaction, deactivates every other location for that platform.
  • Account update (FLAG=U) — a partial update keyed by (supplier, platform, location); no matching row returns “not found”, not an error.
  • Content sync — a batch of at most 20 reviews; the first failing item aborts the whole batch. It resolves the currently-active location (or fails with “create account first”), then upserts each review, deduped on the platform review id.
  • Read — with a platform, paginated reviews for that active account (with a HAS_MORE flag); without one, the top N reviews per platform via a window function.

Sequence diagram · Flows A + C

Linking an account and syncing reviews

Link an account, then sync its reviews:

  1. The sync system links an account; inside one transaction the API upserts the account row active and deactivates other locations for that platform.
  2. It then posts a batch of up to 20 reviews. alt — if no master id was supplied, the API first selects the active location (failing if there is none).
  3. Each review is upserted, deduped on the platform review id, and the batch commits atomically.
  4. A buyer read returns the active account plus paginated reviews (one extra row fetched to compute HAS_MORE); the refresh token is never selected.

Glossary

Business terms used above.

The two objects

Account row
One row per (supplier, social platform, location) — carries the account details, total-rating count and average rating.
Review detail row
One row per individual external review — star rating, comment, reviewer name, and the supplier's reply if any.
Active location
The one location row per platform with display_status = 1. Connecting a new location for the same platform deactivates the previous one (hidden, not deleted).
Organic flag
Marks whether the reviews are genuinely organic or came from a paid / boosted mechanism. Stored, no branching logic on it in these repos.
Refresh token
Stored on the account row for the sync system's use; write-only, never selected or returned on any read path.

The flows

Account link (FLAG=I)
A transactional upsert that marks this location active and deactivates all sibling locations for the platform in the same transaction.
Account update (FLAG=U)
A partial update of just the fields sent; no matching row returns “not found”, treated as a non-error.
Content sync
A batch of at most 20 reviews; the first failing item aborts the whole batch. Needs an active account for the platform or it fails with “create account first”.
Dedupe on platform review id
A re-synced review with the same platform review id updates in place rather than creating a duplicate.
No moderation
The content is already moderated by Google / Facebook, so IndiaMART does not re-scan it (unlike native ratings).

Reads

Single-platform paginated
Reviews for one platform's active account, page by page, with a HAS_MORE flag computed by fetching one extra row.
All-platforms top-N
The most recent N reviews per platform in one round-trip via a window function — avoids a query per platform.
No dedicated read screen
The reviews are surfaced inside the supplier profile response, not a standalone endpoint.
GLID
GlobalID — the unique internal identifier for the supplier whose external reviews are linked.
